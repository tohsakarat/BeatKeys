# 录音匹配语音快捷键

英文名：BeatKeys。

用户配置保存在当前 Windows 用户主目录的 `.beatkeys/config.json`。
首次升级会迁移原安装目录中的配置；已有用户配置不会被覆盖。
初始化数据目录时生成 `README.md`，说明文件用途、录音生物特征隐私和分享注意事项。
录音及配置没有应用层加密，请勿公开上传数据目录。

Windows 图形界面工具。用自己录制的声音样本匹配命令，匹配通过后发送快捷键。没有语音转文字、拼音、KWS 或云端识别。

当前路线为 MFCC 声学特征 → 子序列 DTW → 按键执行队列。日常运行不需要预训练模型、语音转写服务、PyTorch 或 Transformers。

## 启动

发行版直接运行 `dist/BeatKeys.exe`，不需要另行安装 Python。
EXE 使用窗口标题栏的猫头图标，只包含程序、运行依赖和两张界面图片，
不包含开发者的配置、录音或实验模型。首次运行按内置默认值生成用户配置，
包括十条预设命令及英文 ID；已有用户配置保留。

双击 `run.bat`。首次运行需要 Python 和网络，以安装项目虚拟环境中的依赖；之后采集、匹配、样本存储和快捷键发送都在本机完成。

MFCC 不需要加载模型，启动时不再预载 HuBERT。每次匹配会话开始时，从原始 WAV 模板提取 MFCC；录音无需重录。此前下载的模型、已安装的实验依赖和声学模型模块仅保留用于复现实验，GUI 和日常匹配不再加载它们。

## 打包 Windows EXE

在 Windows 项目目录运行：

```bat
.venv\Scripts\python.exe -m pip install pyinstaller==6.22.2 pillow==12.3.0
.venv\Scripts\python.exe build_exe.py
```

产物为 `dist/BeatKeys.exe`，构建中间文件放在 `build/`。
默认配置来自 `user_data.py`，不从当前用户的配置或录音目录读取。

## 设备调试

1. 在输入设备下拉框中选择麦克风。同名设备用音频 API 和编号区分。
2. 点击 **测试麦克风**。不需要录音样本，此模式不发送按键，也不保存录音。
3. 主界面顶部显示紧凑电平条和输入状态，底部为自动滚动的事件日志；**调试**页提供最近两秒的波形、RMS/峰值 dBFS 及最近音频帧时间。
4. 输入削波显示红色；近乎静音、低于语音起点显示黄色；采集到超过起点阈值的输入显示绿色。这些是采集状态，不是识别准确率。
5. 驱动溢出和队列丢块有独立计数。连续两秒没有音频数据会停止会话并显示错误。

波形倍率只放大显示，不改变录音音量或匹配输入。绿色状态也不能证明选到的一定是物理麦克风，虚拟声卡同样可能有音频。

运行中切换设备会先停止旧会话、释放麦克风，再进入新设备的**麦克风调试**，不会自动恢复按键发送。刷新设备列表在停止状态下可用。

当前采集格式是 16 kHz 单声道。如果所选音频接口不支持该格式，界面显示打开设备的具体错误；可选择同一麦克风的另一音频 API 条目。

## 命令与样本

主界面从上到下是麦克风、命令与录音、试匹配与监听。命令列表和所选命令的录音占据主要空间，参数设置与调试信息单独分页。

停止状态下可按住命令行上下拖动排序，松开后自动保存，重启后保持该顺序。拖到列表边缘可滚动；排序不改变命令的快捷键或录音。

拖动上方内容区与下方日志区之间的水平分界条，可调整两部分高度。

1. 点击 **新建命令**，填写显示名称和英文 ID。ID 只能包含小写英文字母和 `-`，例如 `fill-selection`，不可重复，也不能使用 Windows 保留的目录名。点击 **录入快捷键**，按下所需组合键并全部松开后自动填写，也可手动输入。录入时拦截按键以避免触发应用快捷键；点击 **取消录入** 或离开对话框取消监听。编辑命令时同样可重新录入。
2. 左侧选中命令，在右侧点击 **录制首个样本**；已有录音时按钮显示 **再录一个样本**。设备就绪后开始十二秒倒计时，检测到一个完整声段后保存。
3. 录制中点击 **录完**，按当前起止 RMS 阈值裁去首尾静音后保存，开头保留与自动分段相同的缓冲，中间停顿不裁剪。日志显示裁剪前后时长。未达到起音阈值时提示未检测到声音，不保存；手动保存不要求满足最短声段时长。点击 **取消录制** 则不保存。达到自动分段条件仍会自动保存，十二秒超时限制不变。已有录音不自动修改。
4. 右侧列表显示每个样本及其时长。选择样本后可通过播放、删除图标操作，悬停显示名称。试听只在停止状态可用。
5. 编辑命令时可修改英文 ID，保存后当前录音目录下的对应文件夹同步改名，已有 WAV 文件保留。只修改显示名称或快捷键不会改名。旧版本的随机 ID 不会自动替换，可在编辑时自行改成英文 ID。删除命令需确认，并删除它的录音。
6. 播放、删除旁的 **清空** 会在确认后删除当前命令的全部录音，保留命令及快捷键。其他命令的录音不变。

样本保存为 `samples/<command-id>/<number>.wav`，16 kHz、单声道、16 位 PCM。原有命令和样本沿用，不会被界面升级清空。

## 匹配与快捷键

- **试匹配**：只比较录音，不发送按键。底部滚动日志显示匹配结果和计算耗时；**调试**页显示各命令的 DTW 距离。
- **开始监听**：采集分段、识别、按键执行独立运行。完整声段按顺序进入识别队列，匹配通过后进入执行队列，重复命令不会合并或因执行间隔被跳过。日志区分已发送和发送失败。
- **停止** / **取消录制**：运行时替换底部的开始按钮。终止当前会话并释放设备，取消尚未执行的排队命令；已经开始的 DTW 计算结束后才完成停止，但取消后不会发送其结果。

日志在设备就绪时打印“开始工作”，在会话结束、设备释放后打印“结束工作”，并注明工作模式。

试匹配与正式监听使用同一分段和识别队列；正式监听额外排队发送按键。
启动日志记录模式、样本准备耗时及句末静音设置，每个声段记录排队与计算耗时。
排队计时从分段完成开始，不包含说话时长、等待句末静音或界面刷新时间。

没有任何录音时，试匹配和监听按钮不可用；没有选中样本时，试听和删除样本按钮不可用。错误以短摘要显示，点击后滚动到底部查看完整日志。

当前距离为归一化 MFCC 特征的逐帧均方根距离，经 DTW 对齐后求平均。距离越低越相似，不是置信度百分比。使用 `match_threshold`，当前值为 1.1；`hubert_match_threshold` 仅保留供历史实验使用。不要将两种特征的阈值混用。

识别使用子序列 DTW，在一个声段中查找多个命令位置，按距离选择不重叠的命中，再按时间顺序排队。日志记录声段时长、命中次数和每次命中的声段内时间范围。录音样本仍按单条命令录制。

当前版本等声段结束后识别，不是逐字即时触发。达到最长声段时间会强制分段，跨越切分点的命令仍可能漏识别。DTW 通过时间对齐容忍语速变化，但不保证任意快慢都得到完全相同的距离；候选时长暂限于样本特征时长的 0.35–3 倍，且不少于 8 帧（MFCC 帧间隔 10 毫秒）。声音省略、噪声和录音差异仍会影响命中次数。

## 设置

在 **设置** 页调整：

**录音保存目录**默认是当前 Windows 用户主目录下的 `.beatkeys/samples`。可手动填写绝对路径或点击“浏览”，保存后从该目录读取和保存录音。切换目录不会自动合并或搬移其他目录中的录音。本次升级将原项目中的录音迁移到默认目录，命令 ID、文件名及录音内容不变。

**启停快捷键**可点击“录入快捷键”直接按组合键，也可手动填写。点击“保存设置”后全局生效：松开组合键时，空闲状态开始正式监听，工作状态停止当前会话。留空并保存可关闭该快捷键。编辑对话框打开期间不执行启停，退出程序后解除注册。

- 发音容错程度：越大越容易匹配，也越容易误触发；越小越严格。不是百分比。
- 开始收音的音量：声音达到此值才开始收音，调低能捕捉更轻的声音。
- 视为安静的音量：声音低于此值时开始计算安静时间，不能高于开始收音的音量。
- 当前配置的起音 / 结束 RMS 为 0.010 / 0.006，MFCC 匹配阈值为 1.1。十条“撤销”录音在原始模板、排除自身的条件下均各命中一次。保留原始模板，不采用实验中的模板裁剪。这是现有录音上的结果，不代表现场准确率或连续重复计数已验证。
- 说完后等待（秒）：声音持续安静这么久后结束分段并匹配；调短响应更快，但容易拆开一句话。
- 最短 / 最长说话时长（秒）：太短的声音被忽略，达到最长时长时强制分段；手动“录完”不受最短时长限制。
- 两次按键间隔（秒）：连续发送快捷键之间的最短间隔，排队等待而不丢弃命令。

悬停在参数名称或输入框上，可查看调整方向与具体含义。这里只改显示名称，内部参数、数值和行为不变。

设置保存在 `config.json`。采集中参数不可编辑，停止后保存，下次会话使用新值。

## 模块

- `gui.py`：界面、命令管理、样本管理和会话切换。
- `audio_widgets.py`：真实音频波形和命令编辑对话框。
- `audio_session.py`：独占麦克风的调试、录制和识别任务。
- `audio_listener.py`：设备枚举、音频采集、实时电平和驱动状态。
- `speech_segmenter.py`：语音分段。
- `audio_features.py`、`similarity_recognizer.py`：MFCC、DTW 和多次模板匹配。
- `sample_store.py`：WAV 存储。
- `keyboard_controller.py`：快捷键发送。

命令行 `main.py --list-devices` 仅用于设备诊断。日常操作在 GUI 中完成。

## 历史实验

`diagnostics/FEATURE_COMPARISON.md` 记录 MFCC / HuBERT 对比。
`diagnostics/hubert_dtw.py` 和 `diagnostics/hubert_recognizer.py` 固定保存实验使用的 HuBERT 匹配实现，避免切回 MFCC 后复现脚本误用新的距离算法。
`acoustic_features.py` 和 `models/chinese-hubert-base` 只供这些离线实验使用。
